# 会话归并的事件边界

## 背景与问题

#83 要求主、子 agent 的 Toast 使用同一顶层任务累计值。分支已有纯函数归并测试，但事件入口仍存在三类缺口：仅标题更新清掉父子关系；父会话无自身消息时跳过 idle 摘要；插件重启后丢失已持久化的关系。

## 修复与验证

- 父子关系采用与 CLI 一致的非空字段更新口径；仅标题更新不删除已知父关系。
- idle 摘要先归并，再判断整组是否有消息，不以当前 session 自身的统计作为前置条件。
- 启动时流式读取 `sessions.jsonl` 恢复关系，跳过损坏行；缺失或不可读时依赖实时事件继续工作。
- 新增事件回归覆盖多层子会话、其他任务隔离、重复消息、晚到关系、标题更新、父会话无自身消耗、重启恢复和读取降级。最初 6 个用例中有 4 个可复现缺口，修复后补充读取失败用例，7 个全部通过。

## 语义边界

恢复关系不等于回放历史消耗。Toast 仍只汇总当前插件进程收到的消息；完整历史由 CLI 从 tokens.jsonl 读取。会话事件的 parentID 表示父会话，消息事件的 parentID 表示父消息，两者不可混用。

## 可复用结论

纯函数汇总正确，不代表事件接线和生命周期正确。会话树功能至少需要验证“只有子节点有数据”“关系晚到”“部分字段更新”和“进程重启”。
